My homelab

One Proxmox server at home that I run like a small company network: three network zones, single sign-on, automated updates and backups that leave the house.

Why I built it#

I started the homelab in 2025 out of interest: I wanted a place where I can try things that aren't possible in my training, and break them without consequences. Today it also runs services my family and friends use every day, so it has to be reliable.

Hardware

  • ProcessorIntel Core Ultra 7 265KF
  • Memory32 GB
  • System storage2 × 1 TB NVMe
  • Data storage4 hard disks in RAIDZ1 for TrueNAS

How it's built#

A pfSense firewall splits the lab into three zones. Public services live in a DMZ that's cut off from everything else, internal tools stay in the lab network, and test machines get a sandbox of their own.

Admin tools are never exposed directly. I reach them through Cloudflare Tunnels with multi-factor login, which also works from networks where a VPN isn't allowed.

pfSense, pfBlockerNG, Proxmox VE, Cloudflare Tunnel

These are the things people actually use. Everything that's reachable from outside sits behind the same reverse proxy and login, and the admin tools are only reachable for me, through Cloudflare.

Docker, LXC, Nginx Proxy Manager, Crafty Controller, immich

A request from the internet has to pass several checks before it reaches one of my apps. Each layer catches something different, so one mistake in one place doesn't open everything.

Logins use passkeys or authenticator codes wherever I can set them up, including on the firewall, thanks to my own add-on.

pfBlockerNG, CrowdSec, Nginx Proxy Manager, Authentik, Cloudflare Access
  • Updates. I update the whole lab from Ansible playbooks, started in Semaphore. Containers are updated by hand, and Diun e-mails me when a new image is out.
  • Monitoring. Pulse watches every machine and e-mails me when something goes down, and the disks are checked with SMART.
  • Inventory. Netbox lists every machine and IP address, synced from Proxmox automatically.
  • Documentation. A full write-up of the lab, with the decisions behind it and a recovery guide for when something breaks.

Challenges and solutions#

An IP address that kept changing

My services are reached through my own domain, so it has to point to my current home IP (DynDNS). pfSense reported the wrong address: my router uses a 4G booster, and part of the outgoing traffic leaves through the mobile network with a different IP.

Solution: DynDNS now runs on the router itself, which knows the real fixed-line IP. My domain points to that name, so a change at home updates everything automatically.

Too small for photos

At first, everything went through Cloudflare Tunnels. For the photo library that doesn't work: Cloudflare limits the size of a single upload, and videos from a phone are quickly bigger than that.

Solution: I built a DMZ. Public services now come in directly through the firewall to a reverse proxy with single sign-on, while admin tools stay behind the tunnel. That made the whole setup clearer, not just the photo uploads.

What I learned#

  • Many different systemsConfiguring hypervisor, firewall, storage, proxy, identity provider and monitoring, and making them work together.
  • Industry best practicesNetwork segmentation, least privilege, one central login, and backups with an off-site copy.
  • Documentation pays offEvery decision and every recovery step is written down, so a problem at night doesn't start with guessing.
  • Running, not just buildingUpdates, monitoring and alerts are just as much work as setting something up for the first time.

What I'd do differently#

I would plan the DMZ from the start. At first everything ran through Cloudflare Tunnels, and I had to rebuild that later for the photo library.
